# FAULTLINE 다음 버전 설계 — 보상 재편과 타격 연출

작성 기준: 2026-11-11. 이 문서는 다음 버전의 구현 계획이다. 아래 신규 보상·명칭·위험·연출은 아직 게임에 적용하지 않았다. 함께 제공하는 v0.1.1 코드에는 우선 스테이지별 초기화 수정만 반영했다. 신규 수치는 플레이 테스트 전 가설이다.

## 1. 진행 규칙 확정

각 스테이지는 독립된 전투로 시작한다. 보스 처치 → 타격 마무리 → 개조/위험 선택 → 빈 보드에서 다음 스테이지 시작 순서다. 스테이지 승리 후 이전 블록을 가져가지 않는다.

| 구분 | 다음 스테이지에서 처리 |
|---|---|
| 일반 블록, 회색 방해 행, 방해 행 태그 | 전부 제거 |
| 홀드 슬롯의 내용, 홀드 대기 | 초기화 |
| 현재 블록과 다음 블록 | 시드+구역 번호로 새 7-bag 생성 |
| 연쇄, 전하, 고정 유예 시간/초기화 횟수 | 초기화 |
| 수복/차단 등 전투별 사용 횟수 | 현재 개조 등급에 맞춰 재충전 |
| 보스 HP, 공격 주기, 침식, 과부하 고정 수 | 새 보스 기준으로 초기화 |
| 누적 개조, 누적 위험, 보드 높이 개조 | 유지 |
| 런 전체 고정 수, 피해, 시간, 선택 이력 | 유지 |

최종보스의 페이즈 전환은 같은 전투 안의 변화다. 페이즈가 바뀌어도 보드와 사용 횟수를 초기화하지 않는다. 사망하면 개조/위험을 포함한 런 전체가 초기화된다.

v0.1.1에서 기존 수복의 ‘선택 즉시 이전 방해 1행 정리’ 효과는 제거했다. 다음 전투가 빈 보드이므로 실제 가치가 없는 보너스를 설명에 남겨두지 않는다.

## 2. 보상은 총 15개로 재편

기존 12개 중 개시와 전환을 제외하고, 비공격 보상 5개를 추가한다. 보상 수를 무작정 늘리지 않고 9번의 선택에서 방향을 잡을 수 있게 한다. 모든 수치는 각 등급의 누적 총효과다.

| ID | 개조 이름 | 최대 등급 | 다음 버전의 효과 |
|---|---|---:|---|
| single | 집속 렌즈 | 3 | 1줄 피해 +40/80/120% |
| middle | 다중 증폭기 | 3 | 2~3줄 피해 +20/40/60% |
| compress | 압축 장치 | 3 | 4줄 피해 +35/70/105% |
| repeat | 재점화기 | 3 | 이전 제거도 4줄이면 이번 4줄 피해 +25/50/75%. 사이의 비제거 고정은 허용 |
| combo | 증폭 회로 | 3 | 연쇄 추가 단계당 보너스 19/23/27%. 추가 5단계까지 |
| grace | 연쇄 완충기 | 1 | 한 연쇄에서 비제거 고정 1회 허용. 제거할 때마다 허용 횟수를 회복하지 않음 |
| charge | 축전지 | 3 | 비제거 고정마다 전하 1, 최대 4. 다음 제거에 전하당 4/5/6 피해 |
| high | 과부하 회로 | 3 | 제거 직전 천장 여유가 8칸 이하이면 피해 +35/70/105% |
| low | 안정 장치 | 3 | 제거 직전 바닥에서 쌓인 최고 높이가 6칸 이하이면 피해 +15/30/45% |
| repair | 배출 장치 | 3 | 전투당 1/2/3회, 2~3줄 제거 시 태그된 최하단 방해 1행 추가 정리. 6고정 간격 |
| fallControl | 낙하 제어기 | 3 | 자연 낙하 −10/20/30%. 빠른 낙하와 즉시 낙하 유지 |
| landingAssist | 착지 보조기 | 2 | 고정 유예 +75/150ms. 기본 기준 575/650ms. 초기화 15회 상한 유지 |
| extraHold | 보조 저장고 | 1 | 홀드 슬롯 1개 추가. 두 슬롯을 합쳐 한 블록 고정 전 교환은 1회 |
| tallFrame | 확장 프레임 | 1 | 보드 높이 20→22. 폭 10 유지. 바닥과 현재 블록 배열을 유지하고 상단에 빈 2행 추가 |
| guard | 유입 차단기 | 2 | 보스 공격 카운트가 1인 고정에서 2줄 이상 제거하면 예정 방해 1행 차단. 전투당 1/2회 |

‘연쇄 완충기’와 ‘착지 보조기’는 다른 효과이므로 아이콘도 분리한다. 전자는 연결된 회로, 후자는 블록 아래 지지대다. 개조 카드는 이름 → 조건 태그 → 정확한 효과 → 현재 합성 수치 순으로 보여준다.

### 제외 이유

- **개시:** 전투 첫 두 제거의 고정 피해는 후반 가치가 작다. 3등급에 3번 투자해도 총 36 추가 피해로 최종 1600 기본 HP의 2.25%다. 별도 재설계 없이 유틸리티와 경쟁시키면 함정 선택이 될 수 있다.
- **전환:** 이미 3연쇄를 만든 뒤 연쇄가 끝났을 때 전하를 얻는 이중 조건이다. 축전지와 설명이 겹치고, 현재 보상 수에 비해 학습 비용이 크다. 축전지는 남겨 비제거에 투자하는 빌드를 유지한다.

### 유입 차단기 재설계

이전의 ‘최소 1행 유지’ 안은 폐기한다. 기존 대응 패턴이 2행을 1행으로 줄이면 차단기가 작동할 수 없어 무효 선택이 되기 때문이다.

새 규칙은 **조건부로 0행까지 허용**한다. 기존 대응 → 차단기 순으로 처리하고, 실제로 1행을 감소시켰을 때만 사용 횟수를 소모한다. 전투당 최대 2회라 무한 방어가 아니다. 방해가 0행이어도 보스 공격 번호, 재생, 페이즈 예약 진행은 그대로 실행한다. 침식에는 작동하지 않는다. 치명타로 보스를 처치했다면 예정 공격 자체를 취소하므로 차단 횟수도 쓰지 않는다.

배출 장치는 이미 올라온 방해 행을 제거하고, 차단기는 다음 상승을 막는다. 전자는 보드 복구, 후자는 공격 타이밍 관리다. 실제 태그 행을 삭제하지 못했으면 배출 장치도 횟수를 소비하지 않는다.

### 공간 확장과 고층 조건

확장 프레임을 고르면 천장 여유가 2칸 늘어난다. 과부하 회로 조건을 ‘높이 12 이상’으로 유지하면 안전해졌는데도 고층 보너스가 쉽게 붙는다. 다음 버전은 **천장에서 8칸 이하**를 위험 조건으로 사용한다. 따라서 20행 보드에서는 높이 12, 22행에서는 높이 14부터 발동한다. 안정 장치는 바닥 기준 6칸을 유지한다.

가로폭 변경은 별도 보드 유형으로 보류한다. 빈 보드의 4줄을 채우는 셀이 40→48로 늘어나는 등 공격 속도와 안전공간이 함께 바뀌므로 단순한 생존 보상으로 다루지 않는다.

## 3. 추가 위험과 제시 규칙

기존 6개 위험의 이름을 내구도 증가/출력 손실/공격 가속/잔해 유입/자가 복구/고정 유예 단축으로 정리한다. **예고 축소와 주기적 증원을 먼저 추가하여 총 8개로 시험한다.** 저장고 과열과 낙하 가속은 다음 비교 후보로 보류한다.

| 신규 위험 | 가설 수치 | 표시/처리 원칙 |
|---|---|---|
| 낙하 가속 | 자연 낙하 +10/20/30%, 최대 3등급 | 입력 반복 속도와 즉시 낙하는 변경하지 않음 |
| 예고 축소 | NEXT 5→4→3, 최대 2등급 | 고스트와 현재 공격 예고는 유지. 다음 스테이지부터 적용 |
| 저장고 과열 | 홀드 후 2/3개 고정 뒤 재사용, 최대 2등급 | 두 홀드가 대기를 공유. 각 고정 뒤 대기 수를 표시 |
| 주기적 증원 | 매 4/3/2번째 공격에 방해 +1행 | 공격 번호와 추가 행을 먼저 예고. 공격이 끝난 뒤 번호 진행 |

중요한 난이도 가설: 즉시 낙하 숙련자는 낙하 가속과 고정 유예 단축의 비용을 둘 다 작게 느낄 수 있다. 두 종류를 따로 추가하면 ‘유예 단축3 + 낙하 가속3 + 잔해 유입3’으로 부담 9회를 채우는 싼 경로가 늘어난다. 따라서 낙하 가속은 현재 유예 단축과 교체하는 실험부터 한다. 저장고 과열도 보조 저장고의 기본 사용성을 확인한 뒤 검토한다.

첫 구현의 자연 낙하는 `스테이지 기본 속도 × (1 − 0.1×낙하 제어 등급)`이다. 고정 유예는 `500 + 75×착지 보조 등급 − 35×유예 단축 등급`ms이다. 선택 화면에서 각각의 최종 수치를 보여준다.

### 카드 생성

1. 한 화면의 3장에 공격형 최소 1장, 비공격형 최소 1장을 포함한다. 세 번째는 전체 후보에서 추첨한다.
2. 같은 화면에 같은 개조/같은 위험을 반복하지 않는다. 상한에 도달한 후보는 제외한다.
3. 한 카드 안에서 낙하 제어/낙하 가속, 착지 보조/유예 단축, 보조 저장고/저장고 과열을 서로 상쇄하도록 묶지 않는다. 다른 스테이지에서 별도로 고르면 둘 다 누적한다.
4. 현재 효과가 전혀 없는 후보를 제시하지 않는다. 빈 보드에 대한 ‘즉시 수복’ 같은 설명을 만들지 않는다.
5. 특정 시너지 완성을 보장하거나 현재 빌드의 반대 계열을 제거하지 않는다. 최소 역할 다양성과 실제 무효 후보만 관리한다.

### 보류 후보

- **정렬 장치:** 전투당 1회, 다음 공격의 여러 행을 첫 행 구멍에 맞춤. 후반 어긋난 공격을 손쉬운 4줄 재료로 바꾸는지 먼저 시험한다.
- **예측 장치:** 다음 공격의 다음 패턴까지 공개. 페이즈 예약과 장기전 변화가 반영된 조건부 예고가 필요하다.
- 단순 NEXT +2 보상은 기본 5개에 비해 체감이 작을 수 있어 우선 제외한다.

## 4. 현재 연출이 약하게 읽힐 수 있는 코드상 원인

실제 소리를 들은 평가나 사용자 브라우저 FPS 측정 결과가 아니다. `src/fx.mjs`, `src/boss-art.mjs`, `src/audio.mjs`, `src/main.mjs`를 읽고 찾은 강화 지점이다.

1. 삭제된 블록이 27px 셀에 비해 3px 안팎의 점으로 응축된다. ‘방금 지운 줄이 공격으로 바뀌었다’는 질량감이 작다.
2. 1줄부터 4줄까지 같은 사각 탄과 십자형 탄착을 사용한다. 두께/반동만 달라 공격 형태의 차이가 작다.
3. 반동은 주로 보스 전체를 오른쪽으로 움직이는 처리다. 맞은 부위가 먼저 눌리고 다른 장갑이 따라오는 변화가 부족하다.
4. 코어 HP 판정과 초록 HP 바가 즉시 줄고, 탄은 180ms 뒤 도착한다. 탄착과 HP 변화의 시각적 인과를 더 맞출 수 있다.
5. 체력이 줄어도 장갑의 상태가 지속적으로 변하지 않는다. 여러 번 공격한 결과가 보스 외형에 쌓이지 않는다.
6. 합성 효과음은 이미 저음과 노이즈가 있지만 응축/이동/탄착의 역할 분리가 작다. 이 부분은 실제 청취 A/B가 필요하다.

## 5. 다음 타격 타임라인

| 시간 | 연출 | 구현 방향 |
|---|---|---|
| 0~35ms | 삭제 행의 윤곽이 짧게 밝아지고 셀에 절단선 발생 | 실제 삭제 행 스냅샷을 별도 레이어에 잠깐 유지 |
| 20~70ms | 작은 타일 조각이 행 끝의 발사점으로 수축 | 처음에는 원래 블록의 덩어리가 보이고 끝에서 빛으로 응축 |
| 70~180ms | 가속하는 주탄, 짧은 잔상과 보조 입자 | 긴 상시 레이저 대신 탄의 머리·몸통·꼬리 길이를 구분 |
| 180~205ms | 흰 핵과 짧은 충격선, 장갑 눌림, 저음 탄착 | 가장 가까운 장갑이 먼저 반응. 공격 방향으로 충격 벡터 적용 |
| 205~450ms | 장갑 반동과 탄성 복귀, 파편 감쇠 | 코어/내측 장갑/외측 장갑에 서로 다른 스프링과 지연 |
| 강타 시 탄착 직후 | 보스 포즈만 25~40ms 유지 | 논리·블록 낙하·입력·보스 공격 시계는 계속 진행 |
| 치명타 후 약 600ms | 코어 소등 → 장갑 틈 확장 → 외곽 분해 → 보상 | 마지막 공격의 전달이 보인 뒤 메뉴 전환 |

시간은 시작값이며 60/120Hz에서 확인한다. 1줄 연타는 짧고 명료하게 유지한다. 화면 전체를 계속 흔들거나 번쩍이게 하지 않는다.

### 공격별 구분

| 유형 | 형태와 리듬 |
|---|---|
| 1줄 | 날카롭고 가는 탄 1발, 작은 국소 충격 |
| 2~3줄 | 여러 줄의 에너지가 한 탄으로 결합. 탄착에 2~3개의 짧은 갈라짐 |
| 4줄 | 두꺼운 핵과 네 개의 위성 조각. 큰 반동, 낮은 탄착음, 짧은 자세 정지 |
| 높은 연쇄 | 잔상 수와 탄착의 음색이 단계적으로 변화. 밝기/볼륨은 상한 유지 |
| 전하 소비 | 탄 외곽에 앰버색 테두리 추가. 전하가 소비되는 UI와 출발 시점 연결 |
| 차단/수복 | 차단은 보드 하단 방어판, 수복은 해당 방해 행 배출. 보스로 향하는 공격 탄과 구분 |

강도는 줄 수뿐 아니라 공격 피해와 연쇄를 함께 사용한다. 고도 특화 1줄 공격이 큰 피해를 냈는데 언제나 약한 타격으로 보이지 않게 한다. 과장에 상한을 두어 모든 공격이 4줄급 연출이 되지 않게 한다.

### 보스 상태와 사운드

- 일반 보스는 HP 75/50/25% 구간마다 작은 균열과 코어 노출 흔적을 누적한다. 실제 방어/노출 판정과 혼동되는 큰 장갑 제거는 피한다.
- 마지막 타격 방향과 가까운 장갑이 먼저 밀리고, 반대쪽 장갑이 뒤따른다. 평소 부유와 공격 예고는 유지한다.
- 효과음은 절단, 응축, 비행, 탄착의 역할을 분리한다. 강타는 짧은 금속 트랜지언트와 70~95Hz 부근 저음을 시험하되 실제 스피커/헤드폰에서 청취해 결정한다.
- 공격/보드/보스 사운드 버스를 나누고 동시 발음 상한과 마스터 압축으로 연타 시 볼륨 폭증을 막는다. 한 줄 반복은 특히 피로도를 확인한다.

## 6. 코드 경계

| 모듈 | 변경 |
|---|---|
| `core.mjs` | 보상 15종, 새 위험 후보, 매 전투 초기화, 동적 보드 높이, 2홀드/공유 대기, 제한 차단 판정 |
| `main.mjs` | 등급/최종 수치/전투별 횟수 표시, 홀드 선택 UI, 가변 행 수 레이아웃, 시각 HP 별도 상태 |
| `fx.mjs` | 행 스냅샷 조각, 탄 강도/유형, 탄착 방향, 레이어/풀 상한, 치명타 타임라인 |
| `boss-art.mjs` | 부품별 탄성 상태를 받아 그리기, 손상 단계, 타격 포즈 유지 |
| `audio.mjs` | 사건별 음색, 강도 상한, 사운드 버스와 합성 타이밍 |

HP와 승패는 코어에서 즉시 확정한다. HUD의 시각 HP만 탄착 시점에 맞춘다. 연타와 재생이 겹칠 때는 대기 중인 실제 피해량(`hpBefore-hpAfter`)과 실제 회복량을 합산해 표시하고, 오래된 HP 스냅샷으로 새 상태를 덮어쓰지 않는다. FX 종료 콜백으로 실제 피해를 적용하지 않는다.

보드 높이를 늘릴 때 현재의 상수 20, 수복 좌표 제한 19, FX 보드 테두리 높이 등을 함께 제거한다. 런 상태에 행 수를 두고 충돌·스폰·상단 초과·높이 조건·고스트·레이아웃이 같은 값을 참조해야 한다. 기존 10칸 폭과 SRS 킥 테이블은 유지한다.

## 7. 검증과 구현 순서

1. **즉시 수정 v0.1.1:** 매 스테이지 빈 보드·홀드·새 7-bag, 누적 선택 유지. 이 수정은 코드/테스트/빌드에 반영했다.
2. **보상 코어:** 개시/전환 제거, 새 보상과 카드 역할 분배, 등급 상한, 합성 수치 구현.
3. **보드/홀드/차단:** 동적 높이와 2슬롯을 먼저 검증하고, 대응과 차단이 겹치는 0행 공격 및 최종 페이즈 사용 횟수 검증.
4. **타격 1차:** 삭제 행 질량감, 부위별 반동, 탄착과 시각 HP 동기화. 파편 수 증가보다 먼저 작업.
5. **타격 2차:** 공격별 형태, 장갑 손상, 효과음과 치명타 마무리.
6. **플레이 비교:** 기존/개선 연출을 같은 시드·조작 로그로 A/B. 동일한 판정인지 확인한 뒤 체감과 성능을 각각 측정.

게이머 검토의 우선 빌드는 다음 세 종류다. 완성 예시이며 추첨이 항상 이 조합을 보장하지 않는다.

| 9회 선택 예시 | 확인할 실패/성공 형태 |
|---|---|
| 낙하 제어기2 + 착지 보조기2 + 보조 저장고1 + 확장 프레임1 + 다중 증폭기3 | 초보 친화 조작 보상과 최소 공격력이 함께 기능하는지 |
| 과부하 회로3 + 압축 장치3 + 재점화기2 + 확장 프레임1 | 천장 여유 기준에서 높은 위험과 큰 피해가 균형을 이루는지 |
| 다중 증폭기3 + 배출 장치3 + 유입 차단기2 + 증폭 회로1 | 복구와 차단이 무한 생존을 만들거나 장기 정체만 만들지 않는지 |

각 빌드를 부담이 가벼운 경로와 자가 복구/공격 가속/출력 손실 경로에서 비교한다. 구역별 고정 수·실제 피해·회복·보드 최고 높이·사망 원인·사용되지 않은 개조 횟수를 기록한다. 시간은 ‘초’와 ‘고정 수’를 분리한다. 보스 공격/과부하가 고정 수 기준이므로 자연 낙하만 늦췄다고 보스 압박이 줄었다고 판단하지 않는다.

효과 감소 모드에서는 포즈 정지·큰 부유·과한 섬광을 줄이고 행→탄→피격의 관계와 공격 예고는 유지한다. 파편 160개 풀·동시 주탄 6개 등 기존 상한부터 유지하며, 실기 프레임 측정 없이 성능 향상을 단정하지 않는다.
